# Карта репозитория (Repository Map)

Этот документ описывает структуру проекта и назначение его ключевых директорий.

##  Основные директории

### `app/`
Основная директория с исходным кодом приложения.
*   **`blueprints/`** — обработчики маршрутов (контроллеры). Разделены по доменным областям (авторизация, клиенты, материалы, заказы и т.д.).
*   **`dtos/`** — Data Transfer Objects. Классы для передачи данных между слоями приложения (валидация и структурирование данных).
*   **`repositories/`** — слой работы с базой данных. Содержит логику запросов к БД, скрывая детали ORM/SQL от бизнес-логики.
*   **`services/`** — слой бизнес-логики. Здесь происходит обработка данных, вызовы репозиториев и подготовка данных для контроллеров.
*   **`views/`** *(судя по скриншоту, пересекается с blueprints, возможно, содержит рендеринг шаблонов)*.
*   **Файлы конфигурации:** `config.py`, `extensions.py` (инициализация БД, миграций и т.д.), `models.py` (схемы БД), `puzzle_captcha.py` (генерация капчи), `utils.py`.

### `database/`
Содержит SQL-скрипты, не зависящие от ORM.
*   `schema.sql` — DDL-скрипт для создания структуры базы данных.
*   `order_cost_query.sql` — сложные аналитические запросы (вероятно, для расчета себестоимости заказов).

### `tests/`
Директория для тестирования.
*   `conftest.py` — фикстуры и настройки для `pytest`.
*   `test_auth.py`, `test_notes.py` — юнит- и интеграционные тесты для соответствующих модулей.

### `web/`
Статические файлы и шаблоны интерфейса (Frontend).
*   **`.html`** — HTML-шаблоны (Jinja2) для различных страниц (дашборды, списки клиентов, заказов и т.д.).
*   `styles.css` — файл стилей.
*   `image/` — директория с графическими ресурсами (скриншоты/картинки интерфейса).

##  Корневые файлы
*   `run.py` — точка входа для запуска приложения.
*   `requirements.txt` — список зависимостей Python.
*   `.gitignore` — правила исключения файлов из Git.
